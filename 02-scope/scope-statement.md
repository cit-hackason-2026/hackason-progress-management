# スコープ記述書

## プロダクト概要
複数のArduinoマイクロコントローラをI2Cハイブリッド同期方式で連携させ、童謡「きらきらぼし」を主旋律3パート（フルート・クラリネット・オルガン）＋ドラムで自動輪唱演奏する装置「Arduinoオーケストラ：きらきら星 輪唱演奏システム」を開発する。
大学生のストレス回復を支援する受動的環境介入装置であり、利用者の能動的操作を要求せず大学空間に常設できることを目指す。

## スコープ（In Scope）
- 含める機能：
  - Arduino 5台構成（指揮者1台＋楽器スレーブ3台＋リズムスレーブ1台）による「きらきら星」12小節（4/4拍子）の自動輪唱演奏装置の設計・実装
  - I2Cハイブリッド同期方式（小節頭SYNCマーカー＋PLL位相補正）の実装
  - フルート・クラリネット・オルガン・ドラムの倍音加算合成による音色実装（Processing側）
  - ポテンショメータによる可変テンポ制御（BPM変更・PLL収束）の実装
  - ロードセル検知・連続回転サーボモーターによるエンターテインメント機能の実装
  - 装置単体での動作検証（同期精度・音響品質・連続演奏完走率）
- 対象ユーザー：大学生（ストレス回復支援の対象）
- 対象プラットフォーム：大学空間に常設する装置単体（Arduino Uno 5台＋Processing実行PC）

## スコープ外（Out of Scope）
- やらないこと：
  - 社会的効果検証実験（被験者を対象とした急性ストレス回復効果の実証）
  - 利用者の能動的操作を前提とする機能（アプリ操作・予約等）
  - 商業空間向けBGMサービスとしての展開
- 将来検討：社会的効果検証実験を将来研究として別途計画する（本計画書は装置構築までを対象とする）

## 受け入れ基準
- [ ] MOE1：輪唱演奏として音楽的に成立すること
- [ ] MOE2：聴取者が「きらきら星」と識別できること
- [ ] MOE3：聴取者がリラックスできること
- [ ] MOE4：センサ（ポテンショメータ）による可変テンポ制御が演奏中に機能すること

詳細な性能指標は [MOP](../05-quality/mop.md) を参照。

## 最低限ライン（第6週時点の進捗を踏まえた再確認）

第6週時点での進捗（ハードウェア調達・回路構築が進行中、ソフトウェア実装が開始）を踏まえ、最終発表（第11週）に向けて必ず達成すべき最低限の成果物ラインを以下のとおり定義する。

### 必達項目（Must Have）
| 区分 | 最低限ライン |
|------|------------|
| ハードウェア | Arduino 3台以上（指揮者1台＋楽器スレーブ2台以上）の構成でI2C通信による同期演奏が動作すること |
| ソフトウェア | F1同期演奏（I2Cマスタ・スレーブ通信）・F3演奏スケジューリング（「きらきら星」12小節の演奏）・F4音色合成（Processing側、最低2パート以上）・F6通信機能が動作すること |
| 受け入れ基準 | MOE1（輪唱演奏として音楽的に成立）・MOE2（「きらきら星」と識別できる）を満たすこと |
| 成果物 | 動作するハードウェア＋ソフトウェア一式・発表スライド |

### ストレッチゴール（Should / Nice to Have）
| 区分 | ストレッチゴール |
|------|----------------|
| F2 可変テンポ管理 | ポテンショメータによるBPM制御（MOE4）。未達の場合は固定テンポで演奏する |
| F5 エンターテインメント機能 | ロードセル検知・連続回転サーボ演出。未達の場合はボタン等の手動起動で代替する |
| Arduino 5台構成 | 指揮者1台＋楽器スレーブ3台＋リズムスレーブ1台のフル構成。最低3台構成で演奏が成立すれば許容する |
| MOE3 リラクゼーション | 聴取者のリラクゼーション主観評価（MOP5）。音色品質が間に合わない場合は努力目標とする |

### 根拠
- 第6週時点でクリティカルパス（スレーブ側ソフトウェア実装、計53h）の着手が始まったばかりであり、残り5週で全機能を完成させるには高いリスクが存在する
- F5（エンターテインメント機能）・F2（可変テンポ）はMOE1・MOE2達成に必須ではなく、ストレッチゴールに位置づけることでコアシステムの完成を優先する
- スコープ変更は [decision-log](../01-integration/decision-log.md) に記録し、リスク対応は [risk-register](../08-risk/risk-register.md) で管理する
