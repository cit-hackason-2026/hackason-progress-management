# 要件定義

## 機能要件
[FBS](./fbs.md) の主機能 F1〜F6 を機能要件として整理する。優先度はクリティカルパス上の機能（F1 同期演奏・F3 演奏スケジューリング）を高とする。

| ID | 要件 | 優先度 | 備考（対応FBS / MOE・MOP） |
|----|------|--------|------|
| FR-01 | 同期演奏機能：I2C通信によるSYNCマーカー配信とPLL位相補正で全スレーブの小節タイミングを同期する | 高 | F1 / MOE1・MOP1（同期誤差≤30ms）、MOP2（完走率） |
| FR-02 | 可変テンポ管理機能：ポテンショメータでBPMを取得し、変化制限とCONFIG配布でテンポを制御する | 中 | F2 / MOE4・MOP6（変更反映速度）、MOP7（PLL収束速度） |
| FR-03 | 演奏・スケジューリング機能：PROGMEM格納の楽譜データをもとに音符スケジューリングと輪唱位置管理を行う | 高 | F3 / MOE1・MOP1、MOP2 |
| FR-04 | 音色合成機能：各楽器の倍音特性に基づく加算合成とADSRエンベロープでProcessing上に音色を再現する | 中 | F4 / MOE2・MOP4（楽器識別率） |
| FR-05 | エンターテインメント機能：ロードセルによる荷重検知をトリガにサーボ回転演出と演奏開始を制御する | 中 | F5 / 受動性要件（開始トリガ） |
| FR-06 | 通信機能：I2C（Arduino間）とUSB Serial（Arduino-Processing間）の2系統で全ノードを接続する | 高 | F6 / MOP1・MOP2 |

## 非機能要件
| ID | 区分 | 要件 |
|----|------|------|
| NFR-01 | 性能（同期精度） | 楽器間最大同期誤差 ≤30ms（MOP1） |
| NFR-02 | 性能（演奏完走率） | 5台接続・12小節輪唱を10回連続試行し全て完走する（MOP2） |
| NFR-03 | 可用性（冗長性） | I2C通信が一時的に途絶しても各スレーブが自走を継続できること（PLL予測タイマーで演奏を維持） |
| NFR-04 | 保守性 | 共通ライブラリ（PROGMEM＋I2Cフレーム）を整備し、楽器パートごとの実装差分を最小化する |
| NFR-05 | 操作性（受動性） | 利用者の能動的操作を要求せず、大学空間に常設可能であること（座る／荷重をかける動作のみで起動） |

詳細な性能指標と測定方法は [MOP](../05-quality/mop.md) を参照。

## ユーザーストーリー
- 大学生として、装置の前に座って荷重をかけるだけで（能動的なアプリ操作なしに）輪唱演奏が自動的に始まってほしい。作業や休憩のストレスを受動的に和らげるため。
- 大学生として、つまみ（ポテンショメータ）を回すだけで自分にとって快適なテンポに演奏を調整できてほしい。自分に合った心地よい音響環境にするため。
- 聴取者として、流れる演奏が「きらきら星」と自然に識別でき、各楽器の音色が聴き分けられてほしい。音楽として違和感なくリラックスできるため。
- 演奏が完了したら、一定時間後に自動で待機状態へ戻ってほしい。常設装置として手を加えずに繰り返し利用できるため。
